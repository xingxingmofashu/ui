`ToastProvider` wraps Base UI's `Toast.Provider` and supplies the toast manager. Render `Toast` inside it to draw the portal, viewport, and Liquid Glass stack; call `useToast()` anywhere inside the provider to add, update, close, or track notifications.

Render one `ToastProvider` near the app root and place `Toast` after your app content. Each provider owns a separate viewport, so pass the same `toastManager` to it when you also create toasts outside React.

## Basic example

`add` queues a toast with a title, description, and optional type. Toasts dismiss after `timeout` (5000 ms by default), and the timer pauses while the viewport is hovered or focused.

<Example name="toast/basic" />

## Types

`type` selects a built-in status icon: `info`, `success`, `warning`, `error`, or `loading`. Unknown types still render, just without an icon. Use `priority: "high"` for an assertive announcement.

<Example name="toast/types" />

`loading` is rendered automatically by `toast.promise`, so it is usually not created directly.

## Actions

`actionProps` renders an action button inside the toast. Base UI forwards `children` and native button props; close the toast yourself from `onClick` when the action is complete.

<Example name="toast/action" />

## Promise toasts

`toast.promise` starts with a loading toast and updates the same toast to success or error when the promise settles.

<Example name="toast/promise" />

## Positions

`position` anchors the stack to a corner: `top-left`, `top-right`, `bottom-left`, or `bottom-right`. Toasts stack away from the nearest vertical edge, and swipe dismissal follows the anchored corner.

### useToast

`useToast()` returns Base UI's toast manager. It is also available from `@xingxingmofashu/ui/composables/use-toast`.

| Method | Description |
| --- | --- |
| `add(options)` | Adds a toast and returns its ID. |
| `update(id, options)` | Updates an existing toast. |
| `close(id?)` | Closes one toast, or every toast when `id` is omitted. |
| `promise(promise, options)` | Tracks a promise with `loading`, `success`, and `error` options. |
| `toasts` | The current toast objects. |

`add` accepts Base UI's `ToastManagerAddOptions`: `title`, `description`, `type`, `timeout`, `priority`, `actionProps`, and `data`.

`createToastManager` is available from `@xingxingmofashu/ui/composables/create-toast-manager` for toasts created outside React. Attach the manager with the `toastManager` prop before adding notifications so the component can receive them.

## Accessibility

Base UI renders the viewport as a live region, gives high-priority toasts an `alertdialog` role and the rest a `dialog` role, connects titles and descriptions with `aria-labelledby` and `aria-describedby`, and supports F6 focus entry plus swipe dismissal. Timers pause while the viewport is hovered or focused.

When you replace the default close button, give your `close` control an accessible name.

## Styling

The glass surface, stack geometry, and motion are internal. `style` is not supported; tune the shared `--ui-glass-*` tokens or merge layout classes into the viewport with `className`.
