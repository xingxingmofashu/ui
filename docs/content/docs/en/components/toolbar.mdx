`Toolbar` renders one glass bar with actions, toggle buttons, links, groups, and separators. Use it for editor controls, formatting bars, and compact action rows that should share a single keyboard stop. Actions are passed through `items`, and arrow keys move focus inside the bar.

## Usage

### Items

`items` accepts action buttons, toggles, links, groups, and separators. A plain button entry needs no `kind`; pass `label`, `icon`, and native button props such as `onClick` or `disabled`. Icon-only buttons need their own `aria-label`, because icons are decorative.

Use `{ kind: "separator" }` for a divider. A separator defaults to the opposite orientation of the toolbar, so it is vertical in a horizontal bar.

<Example name="toolbar/basic" />

### Toggle

Use `{ kind: "toggle" }` for a two-state action. Pass `pressed` with `onPressedChange` to control it, or `defaultPressed` to let the toolbar manage the initial state. Pressed toggles expose `aria-pressed` and share the glass thumb used by other pressed controls.

<Example name="toolbar/toggle" />

### Group

Use `{ kind: "group" }` for a labelled set of related items. Group entries accept action buttons, toggles, and links through their own `items` array. Give each group an `aria-label` or `aria-labelledby` when it needs a name.

<Example name="toolbar/group" />

### Link

Use `{ kind: "link" }` for navigation. A link entry requires `href` and renders a native anchor, so it keeps standard link behavior. Link entries do not have a disabled state and stay active inside a disabled toolbar or group.

<Example name="toolbar/link" />

### Orientation

`orientation` sets the layout and the arrow-key axis. The default is `"horizontal"`. The example below uses a vertical toolbar next to the value it changes.

<Example name="toolbar/orientation" />

### Size

`xs`, `sm`, `md`, `lg`, and `xl` change item height, padding, text, icons, and separator length. The default is `md`.

<Example name="toolbar/size" />

### Disabled

Set `disabled` on the toolbar to disable its buttons and toggles, or on a button, toggle, or group to disable only that part. Link entries are not affected and stay active. Disabled items stay in the roving focus order by default so keyboard users can discover them; pass `focusableWhenDisabled={false}` on a button or toggle to remove it from that navigation.

## Accessibility

`Toolbar` renders `role="toolbar"` with `aria-orientation`. Name it with `aria-label` or `aria-labelledby`. The bar takes one stop in the Tab order: `ArrowRight` and `ArrowLeft` move focus in a horizontal toolbar, while `ArrowDown` and `ArrowUp` move focus in a vertical one. `loopFocus` defaults to `true`, so focus wraps at the ends.

Toggle items expose `aria-pressed`. Disabled buttons and toggles keep `aria-disabled` and, unless `focusableWhenDisabled` is `false`, remain focusable and are skipped by activation. Groups render `role="group"` and use their `aria-label` or `aria-labelledby`. Separators render `role="separator"` with the orientation opposite the toolbar. Icon-only items need an accessible name through `aria-label` or `aria-labelledby`, and icon slots are hidden from assistive technology. Link items are native anchors and keep the browser's link semantics; they are not disabled by the toolbar and stay in the roving focus order.

See the [accessibility guide](/docs/en/guides/accessibility) for shared focus and keyboard patterns.

## API reference

**Toolbar**

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `readonly ToolbarItemProps[]` | — | Actions, toggles, links, groups, and separators rendered by the toolbar. |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | Layout and arrow-key axis. |
| `loopFocus` | `boolean` | `true` | Wraps focus to the other end when an arrow key passes the last item. |
| `disabled` | `boolean` | `false` | Disables buttons, toggles, and groups while keeping focusable items in the roving focus order. Links are not affected. |
| `size` | `"xs" \| "sm" \| "md" \| "lg" \| "xl"` | `"md"` | Controls item height, padding, text, icons, and separator length. |
| `render` | `ReactElement \| ((props, state) => ReactElement)` | — | Replaces the toolbar root element. |
| `className` | `ClassValue` | — | Tailwind classes merged into the toolbar root. |
| `style` | `CSSProperties` | — | Inline styles merged into the same element as `className`. |
| `ui` | `{ root?: ClassValue; glass?: ClassValue; overlay?: ClassValue; group?: ClassValue; item?: ClassValue; content?: ClassValue; icon?: ClassValue; label?: ClassValue; separator?: ClassValue }` | — | Tailwind classes for internal slots, keyed by `data-slot`. |

Native `<div>` attributes, `aria-*`, and `ref` are forwarded to the toolbar root.

| `disabled` | `boolean` | `false` | Ignores pointer and keyboard activation. |

| `render` | `ReactElement \| ((props, state) => ReactElement)` | — | Replaces the button element or composes it with another component. |
| `className` | `ClassValue` | — | Tailwind classes merged into the button. |
| `style` | `CSSProperties` | — | Inline styles merged into the same element as `className`. |

| Attribute | Description |
| --- | --- |
| `aria-disabled` | Reports a disabled button or toggle item. |

## Theming

The component uses the shared glass material. Tune shared `--ui-glass-*` tokens on a parent, use `className` for layout, and use `ui` for internal slots keyed by `data-slot`. Component-specific values live in `src/theme/toolbar.ts`: `--ui-toolbar-item-height`, `--ui-toolbar-item-px`, `--ui-toolbar-font-size`, `--ui-toolbar-icon-size`, `--ui-toolbar-item-gap`, `--ui-toolbar-padding`, `--ui-toolbar-gap`, `--ui-toolbar-group-gap`, `--ui-toolbar-vertical-radius`, and `--ui-toolbar-separator-length`. The hover fill, pressed thumb, rim, shadow, and divider colors are mixed from `--ui-ink`. See the [theming guide](/docs/en/guides/theming) for token layers and presets.
