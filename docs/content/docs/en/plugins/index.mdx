Plugins are optional package entries that extend the core library without
changing its root import. They are not re-exported from
`@xingxingmofashu/ui`, so an application that does not import a plugin does not
bundle its code or styles.

## Import paths

Plugin entries follow the package structure:

| Entry | Import path |
| --- | --- |
| React or TypeScript module | `@xingxingmofashu/ui/plugins/<name>` |
| Stylesheet | `@xingxingmofashu/ui/plugins/<name>/index.css` |

For example, the glass preset plugin exposes:

```tsx
import {
  GlassPresetProvider,
  GlassPresetScope,
} from "@xingxingmofashu/ui/plugins/glass-preset";
```

```css
@import "@xingxingmofashu/ui/plugins/glass-preset/index.css";
```

The wildcard exports resolve the module at `plugins/<name>/index` and the
optional stylesheet at `plugins/<name>/index.css`.

## Styling

Plugins never import their own stylesheet from the core stylesheet. A plugin
that ships CSS expects an explicit import after the core stylesheet:

```css [app.css]
@import "tailwindcss";
@import "@xingxingmofashu/ui";
@import "@xingxingmofashu/ui/plugins/glass-preset/index.css";
```

Keeping plugin CSS opt-in means the core stylesheet works on its own and unused
plugin styles stay out of the build.

## Client boundaries

Plugins follow the same React boundaries as the core components. Modules that
use hooks or browser APIs carry the `"use client"` directive. Server-safe
helpers, such as the glass preset script generator, can be rendered or called
from a server component. Check each plugin page for the exact entry points.
