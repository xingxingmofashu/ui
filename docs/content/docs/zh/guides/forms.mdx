表单控件优先遵循原生 `<form>` 行为。`Input` 渲染原生 `<input>`；`Checkbox`、
`Switch` 与 `Slider` 则渲染内部原生输入用于提交。因此 `FormData`、Server
Actions 与渐进增强模式都能继续使用，不需要自定义状态容器。

## 提交的值

| 组件 | 提交形式 | 空状态 |
| --- | --- | --- |
| `Input` | 由 `name` 命名的原生输入 | 空字符串 |
| `Checkbox` | 带 `name` 与 `value` 的隐藏 checkbox | 未选中时为 `null` |
| `Switch` | 带 `name` 与 `value` 的隐藏 checkbox | 关闭时为 `null` |
| `Slider` | 由 `name` 命名的隐藏 `input[type="range"]` | 当前值 |

`Button` 会把 `type` 转发给根 button 元素。需要提交表单时设置
`type="submit"`。

```tsx
<form action={savePreferences}>
  <Input label="邮箱" name="email" type="email" required />
  <Switch label="通知" name="notifications" value="enabled" />
  <Button type="submit" label="保存" />
</form>
```

在客户端处理提交时，从 `FormData` 读取值：

```tsx
function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
  event.preventDefault();
  const data = new FormData(event.currentTarget);
  const email = String(data.get("email") ?? "");
  const notifications = data.get("notifications") !== null;
  // 将值发送到 API，或更新本地状态。
}
```

## 标签与描述

使用内置的标签属性，而不是另外渲染文本：

- `Input` 渲染与输入框关联的真实 `<label>`。
- `Checkbox` 与 `Switch` 使用可见标签作为可访问名称。
- `Slider` 不渲染可见标签，因此请用 `aria-labelledby` 指向外部标签。

描述会通过 `aria-describedby` 自动关联。如果传入自己的
`aria-describedby`，它会与自动生成的值合并。

```tsx
<div className="flex flex-col gap-2">
  <span id="volume-label" className="text-sm text-ui-ink">
    音量
  </span>
  <Slider aria-labelledby="volume-label" name="volume" defaultValue={40} />
</div>
```

对于一组相关控件，使用原生 `<fieldset>` 与 `<legend>`：

```tsx
<fieldset className="flex flex-col gap-3">
  <legend className="text-sm font-medium text-ui-ink">通知</legend>
  <Switch label="邮件" name="email-notifications" value="on" />
  <Switch label="@ 提及" name="mention-notifications" value="on" />
</fieldset>
```

## 受控与非受控

每个有状态控件都支持两种模式：

```tsx
// 非受控：组件自己持有状态。
<Input label="姓名" name="name" defaultValue="Ada" />
<Switch label="公开资料" name="public" defaultChecked />

// 受控：由你持有状态。
const [email, setEmail] = useState("");
<Input
  label="邮箱"
  name="email"
  value={email}
  onValueChange={setEmail}
/>
```

不要只传 `value` 而不提供变更处理函数。对于 `Slider`，`onValueChange` 会收到
当前数字或数组；只关心稳定值时使用 `onValueCommitted`。

## 校验

`required`、`minLength`、`pattern`、`type` 等原生约束会转发到输入框。自定义
校验时，把错误信息放在字段旁边，并用 `aria-describedby` 或
`aria-errormessage` 关联：

```tsx
import { useState } from "react";
import { Input } from "@xingxingmofashu/ui";

function EmailField() {
  const [email, setEmail] = useState("");
  const invalid = email.length > 0 && !email.includes("@");

  return (
    <div className="flex flex-col gap-2">
      <Input
        label="邮箱"
        name="email"
        type="email"
        value={email}
        onValueChange={setEmail}
        aria-invalid={invalid || undefined}
        aria-describedby={invalid ? "email-error" : undefined}
      />
      {invalid ? (
        <p id="email-error" className="text-sm text-ui-ink/70">
          请输入有效的邮箱地址。
        </p>
      ) : null}
    </div>
  );
}
```

`Slider` 会把 `aria-invalid` 与 `aria-errormessage` 转发到内部的 range
输入，因此校验状态能到达可聚焦控件。`Checkbox` 与 `Switch` 会转发属性与
隐藏输入，同样适用。

## 禁用与只读

- `disabled` 阻止交互，并从表单提交中移除控件。
- `readOnly` 保留焦点与选择能力，但阻止修改。
- `Button` 的 `focusableWhenDisabled` 会让禁用操作保留在 Tab 顺序中，同时暴露
  `aria-disabled` 并阻止激活。

用户需要复制值时使用只读；当前状态下不相关的控件使用禁用。

## Server Actions

由于控件通过原生输入提交，React 19 Server Action 可以直接接收普通
`FormData`：

```tsx
"use server";

export async function savePreferences(formData: FormData) {
  const email = String(formData.get("email") ?? "");
  const notifications = formData.get("notifications") !== null;
  // 持久化这些值。
}
```

`action` 属性属于外层 `<form>`；组件只负责提供字段。

## 常见问题

- 只传 `value` 而不传 `onValueChange` 会让受控字段冻结。
- 在 submit 事件之前读取 `FormData` 会得到旧值或空值。
- 关闭的 `Switch` 提交 `null`，而不是 `"false"`，请显式归一化。
- `Slider` 需要可访问名称；标签渲染在组件外部时，`aria-labelledby` 通常最清晰。
- 不要自己用 `<label>` 包裹控件；组件已经渲染正确的标签关系。
